## Краткий итог

Подготовлены план и минимальный CPU-прототип ключевой операции: резервирование, запись, чтение и освобождение KV-данных при непрерывном и страничном размещении. Используются настоящие массивы `bytearray`; зависимости кроме Python отсутствуют. Успешно выполнены **6 unit-тестов** и **6 сценариев с аналитически известным ответом**. Доступны журналы памяти, отказов, резидентных запросов и длительности операций.

Основные технические предпосылки подтверждены: описание механизма достаточно для самостоятельной реализации, нет обязательной зависимости от GPU/vLLM, фиксированные примеры совпадают с расчётом. Полный динамический обработчик, основные серии и итоговые выводы к этой точке не заявляются. ФИО, согласованный вклад, публикация PR и регистрация требуют завершения организационных действий, перечисленных в [status.md](../status.md).

Общая команда: из корня репозитория `python3 scripts/checkpoint.py --output /tmp/team14-checkpoint-1`. | Проверка | Ожидаемый результат | Полученный результат и свидетельство |
|---|---|---|
| Реальная память и round-trip | Физический пул имеет фиксированную длину; прочитанные байты равны записанным; обращение к физически несмежным страницам прозрачно | `bytearray` и проверка содержимого в [аллокаторах](../../kv_cache/allocators.py), тест `test_noncontiguous_page_translation`: таблица `[2, 0]`, данные сохранены; [tests.log](../../artifacts/checkpoint-1/tests.log) |
| Внутренняя неиспользуемая ёмкость | Два запроса, пределы 8/8, длины 3/5, s=8, B=4: C резервирует 16×8=128 байт; P — (4+8)×8=96; полезно 64 у обоих | В `memory`: C=128, P=96, полезно=64; slack 64/32. Физический пул у обоих 128 байт |
| Ёмкость при завышенных пределах | Пул 32 токена, предел каждого 16, реально записано 4, B=4, s=16: C держит 2 запроса, P — 8; следующая попытка даёт OOM | В `capacity`: 2/8 резидентных запросов, по 1 отказу, занято 512 байт у обоих; это не измерение динамического пакета |
| Внешняя фрагментация | Пул 12 токенов, три диапазона по 4; освободить первый и третий. Свободно 8, крупнейший непрерывный участок 4; запрос 6 не помещается в C, но помещается в P при B=2 | `holes`: до попытки свободно 64 байта, у C крупнейший участок 32 и ratio=0.5; C отказал, P записал все 6 токенов |
| Граница страницы и OOM | Неудачный append не меняет длину и старое содержимое; после free соседнего запроса рост успешен | `test_page_boundary_failure_and_reuse` пройден; снимки и байтовые сравнения в [тестах](../../tests/test_allocators.py) |
| Повторное использование и инварианты | После полного освобождения пул целиком свободен; нет пересечений и утечек; некорректные операции отклоняются | Для обоих методов выполнено по 1000 псевдослучайных операций, seed 14, с независимым oracle; все 6 тестов успешны |
| Доступность данных метрик | Журнал содержит ёмкость пула, занято/полезно/slack/free, активные последовательности, отказы, длительность операции | Поля `pool_payload_bytes`, `allocated_bytes`, `live_bytes`, `slack_bytes`, `free_bytes`, `active_requests`, `allocation_failures`, `duration_ns` есть в событиях [results.json](../../artifacts/checkpoint-1/results.json) |

Отдельный запуск тестов: `python3 -m unittest discover -s tests -v`. Ожидается `Ran 6 tests` и `OK`; именно такой результат сохранён в [tests.log](../../artifacts/checkpoint-1/tests.log). Итоговое освобождение проверяется для всех шести сценариев, в JSON есть `cleanup_snapshot`.

Пробные `duration_ns` — wall-clock длительности API аллокатора, без инвариантов и формирования snapshot. Это свидетельство работоспособности таймера, а не сравнение скорости LLM. Поля задержек целого запроса и размера динамического пакета добавляются вместе с обработчиком к КТ2 по [плану](../experiment-plan.md#метрики). Контрольные суммы кода, конфигурации и результатов — [sha256.json](../../artifacts/checkpoint-1/sha256.json).

## Ресурсы

Проверки выполнены на macOS 26.6.2 arm64, Python 3.9.6, 12 логических CPU, 25 769 803 776 байт RAM (24 ГиБ). Окружение автоматически записано в результатах. Максимальный payload пула текущих примеров — 512 байт; это проверка операции, не стресс-тест ресурсов.

Для будущих серий выбраны пулы 8–128 МиБ и один поток. На машине с 8–16 ГиБ RAM этого должно хватить с учётом Python-метаданных; фактический RSS и время будут проверены пилотом до 25.11.2026. Отдельных GPU, облачных квот или закрытых данных не требуется. Доступность машины для всех будущих запусков команда должна подтвердить; текущее окружение подтверждает только состоявшийся локальный запуск.
