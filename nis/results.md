# Данные и результаты

## Первая контрольная точка

Содержит технические проверки операции размещения, а не полные сравнительные эксперименты.

```bash
python3 scripts/checkpoint.py --output /tmp/team14-checkpoint-1
```

Команда запускается из корня на Python 3.9+. Вход: [configs/checkpoint-1.json](../configs/checkpoint-1.json), фиксированные последовательности reserve/append/free в [scripts/checkpoint.py](../scripts/checkpoint.py), seed 14 в тесте случайных операций. Никакие данные из сети не требуются. Начальное состояние каждого сценария — новый нулевой пул.

Сохранённый запуск от 03.11.2026:

- [Сводная таблица](../artifacts/checkpoint-1/summary.md).
- [Исходные события и окружение](../artifacts/checkpoint-1/results.json).
- [Вывод тестов](../artifacts/checkpoint-1/tests.log).
- [SHA-256 кода, конфигурации и артефактов](../artifacts/checkpoint-1/sha256.json).

В `results.json` каждый из шести элементов `cases` содержит параметры, события операций, `checkpoint_snapshot` для таблицы и `cleanup_snapshot` после освобождения. В `holes` есть отдельный снимок до попытки размещения. `allocation_failures` — накопленный счётчик неудачных вызовов API внутри текущего сценария; в будущих сериях ошибки запросов будут отдельной метрикой.

Все размеры payload в байтах. `pool_payload_bytes` — размер физического массива, `allocated_bytes` — его закреплённая часть, `live_bytes` — реально записанные токены. `slack_bytes` включает избыточный резерв и незаполненные хвосты; это не RSS. `active_requests` — резидентные последовательности. У paging `largest_free_span_bytes=null`, поскольку смежность блоков не требуется. `duration_ns` — один вызов reserve/append/free, включая запись payload, исключая последующие инварианты и формирование события. Входной payload вычисляется до вызова.

Скрипт строит таблицу и манифест после успешных тестов и аналитических assert-проверок. Повторный запуск в новый каталог сохраняет исходные свидетельства. При повторе должны совпасть конфигурации, ответы проверок и детерминированные снимки памяти; дата, тайминги и зависящие от них SHA результатов отличаются. Контрольные суммы исходников позволяют установить точную версию проверявшегося кода ещё до публикации коммита.
