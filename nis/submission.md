## Действия перед публикацией

1. Участники и равномерный план работы уже внесены в [team.md](team.md), README и карточку КТ1. Дописать скрытое имя Галимова; каждому приложить ссылки на фактически выполненные задачи и проверки.
2. Повторить `python3 scripts/checkpoint.py --output /tmp/team14-checkpoint-1`.
3. Авторизовать GitHub CLI командой `gh auth login`. Не вставлять токены в файлы проекта или сообщения.
4. Начальный коммит в `main` с `.gitignore` и ветка `nis/checkpoint-1` с материалами уже созданы локально. Галимов публикует обе ветки через обычные `git push`, без переписывания истории. Не помещать все материалы сразу в main: иначе PR не покажет сдаваемую разницу.
5. Все исправления добавлять новыми коммитами после просмотра списка файлов и diff на секреты. Галимов фиксирует полный `git rev-parse HEAD` и открывает PR в main через GitHub. В описание включить этот SHA, краткий результат и ссылки на три документа и технические свидетельства на данном SHA. PR пока не объединять.
6. Обновить `status.md`: фактические ссылки на PR и коммит, подтверждение регистрации. Исправления после фиксации сдачи добавлять отдельным коммитом; в описании PR явно указывать, какой SHA проверяется.
7. Галимов отправляет форму регистрации: команда 14, P23, URL репозитория и остальные запрошенные сведения представителя. Егор проверяет запуск по README, Григорий — доступность результатов и ссылок. Перед отправкой убедиться, что преподаватель может просматривать код и комментировать PR. Для публичного GitHub-репозитория с открытыми комментариями добавлять преподавателя отдельно не требуется.

После создания локального коммита полный SHA следует получить командой `git rev-parse HEAD` в ветке `nis/checkpoint-1` и указать в описании PR. Сейчас ссылка на PR и факт отправки формы не заявляются. После дедлайна не выполнять rebase и force-push ветки сдачи; исправления добавляются новыми коммитами.
